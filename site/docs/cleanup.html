Suggestions and undo

Analysis rebuilds duplicate groups, version chains, projects and the health score after every scan, and turns what it finds into suggestions. A suggestion is a proposal; nothing runs from it until you preview and apply it in Assist mode.

Kinds

KindWhat it proposesTier
DuplicateTrash exact copies; keep the one in the most deliberate place with the cleanest name.2
Duplicate folderA whole folder that is a byte-for-byte copy of another (creditos-v1 of creditos), trashed as one step.2
VersionsTuck report_v1…v5 into a report versions folder beside the newest.1
Stale downloadsMove loose files untouched for 90+ days into ~/FileMind Archive/Downloads/<year>/<month>/.1
ShrinkRewrite cold text, code and raw-format files in place with APFS transparent compression: same file, same contents to every app, fewer bytes on disk. Proposed only after filemind shrink estimate (or the Overview tile) has measured the ratio, in batches of up to 500 files. Never sensitive files, app bundles, Library, or files another program has open.1

Preview → apply

The preview lists every KEEP, MOVE, TRASH and SHRINK line with the exact paths, plus any problems (a file that changed since analysis, a destination that already exists). Apply runs the plan you saw — the transaction carries the previewed id and a fingerprint of its steps, so a plan that changed underneath you is refused rather than run.

Undo

History lists every transaction. Undo restores each step from the journal; a file edited after it was moved, or a destination that is now occupied, is left alone and reported rather than clobbered. For transactions that only trashed things the button reads Put back. A Shrink step is undone in place: the plain copy is written back and the file keeps its identity; if the file was edited after it was compressed (macOS decompresses it on the first write anyway), it is left as is.
