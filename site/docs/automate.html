Automate mode

Automate lets a small allow-list of rules run without asking each time. The allow-list is code, not configuration; only these three kinds exist, and each has bounded parameters:

RuleWhat it doesBounds
archive_stale_downloadsMove loose files sitting directly in Downloads, untouched for N days, into the dated archive.N ≥ 30; ≤ 500 per run; hidden files and subfolders never
collapse_versionsTuck older versions with explicit markers (v2, copy, final) into a versions folder.chain untouched ≥ 7 days; bare-number series left alone
trash_exact_duplicatesTrash exact copies in Downloads whose kept copy lives elsewhere and is verified present.≥ 64 KB; untouched ≥ 7 days

The preview week

A new rule starts in preview. Every agent tick it records a dry run — the exact list it would have moved — and the Automate screen shows “in the last 7 days this rule would have moved N files”. Only after seven days, and at least one dry run, can it be armed.

When it runs

An armed rule executes only while the mode is Automate, as a normal journaled transaction with the rule as initiator. It appears in History and can be undone like anything else. Any validation problem, failed step, or a plan larger than the rule's pause_above pauses the rule with the reason; arming again is a deliberate act.

Backlog first, rule second: if hundreds of files qualify, apply the Assist-mode Stale downloads suggestion once (one reviewable transaction), then let the rule keep the folder tidy at 50 files a run.

From the terminal

filemind rule kinds
filemind rule add archive_stale_downloads --set older_than_days=120
filemind rule                     # what each rule would have done
filemind rule preview 1           # right now, touches nothing
filemind rule arm 1               # after the preview week
filemind mode automate
